# ProdFlow 0.1.0 — pakiet przekazania do Jira

Data przekazania: 15 listopada 2026 (Europe/Warsaw). Wykonanie i testy: 14 listopada 2026. Stan: gotowe do przeglądu zespołu, bez zatwierdzenia produkcyjnego.

## Zawartość

- Kod React/TypeScript/Vite i NestJS, kontrakty API, SQL PostgreSQL, sterowniki PostgreSQL/PGlite.
- Dwie migracje, fikcyjne dane demonstracyjne, logowanie z rolami i sesjami.
- Panel kierownika, tworzenie zleceń z audytem, podgląd zadań i obecności; wariant mobilny.
- Testy SQL/HTTP, konfiguracja CI, formatowanie, skrypty konfiguracji i uruchomienia.
- README, architektura, przegląd PW-20, raport testów, analiza PW-17, materiały źródłowe i zrzuty UI.
- Przypięte zależności w pnpm-lock.yaml. ARCHIVE-MANIFEST.json w ZIP zawiera spis i SHA-256 każdego pliku. Osobny plik SHA256SUMS.txt identyfikuje cały ZIP.

Pakiet pomija rzeczywisty .env, hasła, tokeny, lokalne dane PGlite, node_modules, cache, pliki robocze i wynik kompilacji. Pozostawia .env.example z placeholderami. Konta demonstracyjne tworzy instalator z nowym losowym hasłem na komputerze odbiorcy. Załączony kod nie zawiera danych rzeczywistych pracowników.

## Odtworzenie

1. Rozpakować ZIP. Otworzyć terminal w katalogu prodflow.
2. Zapewnić Node.js 22.12+ i pnpm 11.25.0.
3. Wykonać `pnpm install --frozen-lockfile`.
4. Wykonać `node scripts/start-local.mjs`.
5. Otworzyć `http://localhost:5173`. Loginy: kierownik / pracownik. Hasło jest w nowo wygenerowanym `.env`, pole DEMO_PASSWORD.
6. Weryfikacja: `node scripts/verify.mjs`. OpenAPI: `/api/docs` przez ten sam lokalny adres.

## Ograniczenia i dalsza realizacja

To szkielet, nie całe MVP. Rejestracja wejścia/startu/pauzy/wznowienia/końca/wyjścia, korekty, skanowanie i wystawianie QR oraz tryb offline nie są zaimplementowane. Tabele terminali, wyzwań i idempotencji stanowią przygotowanie do tych operacji.

Weryfikacja odbyła się na lokalnym PGlite. Docker Desktop nie uruchomił demona; testy na serwerze PostgreSQL, wyścigi wielu połączeń, obciążenie, backup/restore i wdrożenie pozostają do wykonania. Konfiguracja GitHub Actions jest plikiem w kodzie; nie ma jeszcze wyniku z uruchomionego CI.

Priorytet następnego etapu: PW-10/PW-11 operacje czasu i ich reguły transakcyjne; następnie PW-12 terminal/QR/PWA. CRUD administracyjny i raporty rozwijać w odpowiednich epikach PW-6–PW-9/PW-13. PW-14, PW-15 i PW-16 obejmują dalsze rozszerzenia, testy akceptacyjne i wdrożenie. Przekazanie tej paczki nie oznacza ukończenia tych epików.
